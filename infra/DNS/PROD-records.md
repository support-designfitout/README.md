## Overview

The DNS configuration enables:
- **Email**: Google Workspace email with SPF, DKIM, DMARC, and MTA-STS
- **Website**: Cloudflare-hosted website with SSL/TLS
- **Security**: Email authentication and transport security

## Required Records

### A Records (Website Hosting)

| Type | Name | Content | TTL | Proxied | Notes |
|------|------|---------|-----|---------|-------|
| A | designfitout.com | `<YOUR_ORIGIN_IP>` | 3600 | ✓ Yes | Main website - replace with your server/Pages IP |
| A | www | `<YOUR_ORIGIN_IP>` | 3600 | ✓ Yes | WWW subdomain (optional) |
| A | mta-sts | `<YOUR_ORIGIN_IP>` | 3600 | ✓ Yes* | MTA-STS policy endpoint |

**\*MTA-STS Proxied Note**: Can be proxied if served via Cloudflare Pages/Workers. Must serve the policy file at `/.well-known/mta-sts.txt` (see `functions/.well-known/mta-sts.txt.ts`).

### MX Records (Email Routing)

| Type | Name | Content | Priority | TTL | Proxied | Notes |
|------|------|---------|----------|-----|---------|-------|
| MX | designfitout.com | aspmx.l.google.com | 1 | 3600 | ✗ No | Primary Google mail server |
| MX | designfitout.com | alt1.aspmx.l.google.com | 5 | 3600 | ✗ No | Backup mail server |
| MX | designfitout.com | alt2.aspmx.l.google.com | 5 | 3600 | ✗ No | Backup mail server |
| MX | designfitout.com | alt3.aspmx.l.google.com | 10 | 3600 | ✗ No | Backup mail server |
| MX | designfitout.com | alt4.aspmx.l.google.com | 10 | 3600 | ✗ No | Backup mail server |

**Critical**: MX records **MUST NOT** be proxied. Set `proxied=false`.

### TXT Records (Email Authentication)

#### SPF Record
| Type | Name | Content | TTL | Proxied |
|------|------|---------|-----|---------|
| TXT | designfitout.com | `v=spf1 include:_spf.google.com ~all` | 3600 | ✗ No |

**Purpose**: Authorizes Google Workspace to send email on behalf of your domain.

**Breakdown**:
- `v=spf1` - SPF version 1
- `include:_spf.google.com` - Include Google's SPF record
- `~all` - Soft fail for unauthorized senders (recommended for initial setup)
  - Alternative: `-all` (hard fail, more strict - use after testing)

#### DMARC Record
| Type | Name | Content | TTL | Proxied |
|------|------|---------|-----|---------|
| TXT | _dmarc.designfitout.com | `v=DMARC1; p=none; rua=mailto:dmarc@designfitout.com; pct=100; adkim=s; aspf=s` | 3600 | ✗ No |

**Purpose**: Specifies email authentication policy and reporting.

**Breakdown**:
- `v=DMARC1` - DMARC version 1
- `p=none` - Policy: monitor only (recommended for initial 7-14 days)
  - Upgrade path: `p=none` → `p=quarantine` → `p=reject`
- `rua=mailto:dmarc@designfitout.com` - Aggregate report email address
- `pct=100` - Apply policy to 100% of emails
- `adkim=s` - Strict DKIM alignment
- `aspf=s` - Strict SPF alignment

#### DKIM Records
| Type | Name | Content | TTL | Proxied |
|------|------|---------|-----|---------|
| TXT | google._domainkey.designfitout.com | `<GENERATED_BY_GOOGLE_WORKSPACE>` | 3600 | ✗ No |

**Note**: DKIM record is generated by Google Workspace after domain verification. See [Google Workspace Setup Guide](../../docs/GoogleWorkspaceSetup.md) for instructions.

**Example DKIM record format**:
```
v=DKIM1; k=rsa; p=MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEA...
```

#### MTA-STS Record
| Type | Name | Content | TTL | Proxied |
|------|------|---------|-----|---------|
| TXT | _mta-sts.designfitout.com | `v=STSv1; id=2025-11-09` | 3600 | ✗ No |

**Purpose**: Indicates MTA-STS policy availability and version.

**Notes**:
- Update `id` value when policy changes to force cache refresh
- Format: `id=YYYY-MM-DD` or any unique string
- Must match policy served at `https://mta-sts.designfitout.com/.well-known/mta-sts.txt`

## Cloudflare Proxy Configuration

### When to Use Cloudflare Proxy

| Record Type | Proxy Recommendation | Reason |
|-------------|---------------------|---------|
| A (website) | ✓ **Yes** | CDN, DDoS protection, SSL/TLS |
| A (mta-sts) | ✓ **Yes** | Can proxy if serving policy via Cloudflare |
| MX | ✗ **No** | Email routing requires direct DNS |
| TXT | ✗ **No** | Authentication records must be direct |

### SSL/TLS Configuration for Proxied Records

When using Cloudflare proxy for website and MTA-STS:

1. **Recommended**: Full (Strict) mode
   - Cloudflare ← HTTPS → Origin Server
   - Requires valid SSL certificate on origin
   - Best security

2. **Alternative**: Full mode
   - Cloudflare ← HTTPS → Origin Server
   - Accepts self-signed certificate on origin
   - Good security

3. **Not Recommended**: Flexible mode
   - Cloudflare ← HTTP → Origin Server
   - No encryption between Cloudflare and origin
   - Poor security

**To Configure**:
1. Go to Cloudflare Dashboard → SSL/TLS
2. Select "Full (Strict)" encryption mode
3. Ensure origin server has valid SSL certificate (Cloudflare Origin Certificate or Let's Encrypt)

### MTA-STS Proxy Considerations

If proxying the MTA-STS subdomain through Cloudflare:
- ✓ Cloudflare automatically provides SSL certificate
- ✓ Policy file must be served by Cloudflare Pages Function or Worker
- ✓ Deploy `functions/.well-known/mta-sts.txt.ts` to Cloudflare Pages
- ✓ Verify policy accessible at: `https://mta-sts.designfitout.com/.well-known/mta-sts.txt`

## TTL Recommendations

| Scenario | Recommended TTL | Reason |
|----------|----------------|---------|
| Initial Setup | 300-600 seconds | Allows quick changes during testing |
| Production | 3600 seconds (1 hour) | Balance between performance and flexibility |
| Stable Production | 14400-86400 seconds | Maximum caching for mature, stable records |

**Current Configuration**: All records use TTL=3600 (1 hour)

## Important Notes

### DNS Propagation
- **Local/ISP**: 5-15 minutes
- **Global**: 24-48 hours (typically faster)
- Use `dig @8.8.8.8` to query Google's DNS directly for immediate verification

### Email Authentication Testing Tools
- **MXToolbox**: https://mxtoolbox.com/SuperTool.aspx
- **Google Admin Toolbox**: https://toolbox.googleapps.com/apps/checkmx/
- **DMARC Analyzer**: https://dmarcian.com/dmarc-inspector/
- **MTA-STS Validator**: https://aykevl.nl/apps/mta-sts/

### Common Issues

#### Issue: MX records not resolving
**Solution**: Ensure `proxied=false` for all MX records in Cloudflare

#### Issue: SPF lookup failures
**Solution**: Verify SPF record syntax, limit to max 10 DNS lookups

#### Issue: DMARC reports not received
**Solution**: 
- Check email alias dmarc@designfitout.com is configured
- Reports may take 24-48 hours to start arriving

#### Issue: MTA-STS policy not accessible
**Solution**:
- Verify mta-sts A record points to correct IP
- Ensure Cloudflare Pages Function is deployed
- Check SSL certificate is valid

### Security Best Practices

1. **Start Conservative**:
   - Begin with `p=none` for DMARC
   - Use `~all` for SPF initially
   - Monitor reports for 7-14 days

2. **Progressive Enhancement**:
   - Week 1-2: `p=none` (monitor)
   - Week 3-4: `p=quarantine` (quarantine suspicious emails)
   - Week 5+: `p=reject` (reject unauthorized emails)

3. **Regular Monitoring**:
   - Review DMARC reports weekly
   - Monitor email delivery rates
   - Check MTA-STS policy effectiveness

4. **Update MTA-STS Policy ID**:
   - When changing MTA-STS policy, update the `id` in DNS record
   - Forces email servers to fetch fresh policy
   - Example: Change `id=2025-11-09` to `id=2025-11-16`
