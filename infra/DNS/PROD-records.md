## MTA-STS Subdomain

### mta-sts.designfitout.com

The MTA-STS subdomain serves the email security policy at `https://mta-sts.designfitout.com/.well-known/mta-sts.txt`.

```
Type: A (or CNAME)
Name: mta-sts
Content: <Same_as_Root_or_Cloudflare_Pages_IP>
TTL: 3600 (1 hour)
Proxy: ✅ Enabled (Recommended if served through Cloudflare Pages)
```

**Alternative with CNAME**:
```
Type: CNAME
Name: mta-sts
Content: designfitout.com
TTL: 3600 (1 hour)
Proxy: ✅ Enabled
```

**Requirements**:
- Must be accessible over HTTPS (TLS certificate required)
- Should return the MTA-STS policy file at `/.well-known/mta-sts.txt`
- Cloudflare Pages Function handles this automatically (see `functions/.well-known/mta-sts.txt.ts`)

## TXT Records (Email Security)

### SPF (Sender Policy Framework)

Authorizes Google Workspace to send email on behalf of your domain.

```
Type: TXT
Name: @
Content: v=spf1 include:_spf.google.com ~all
TTL: 3600 (1 hour)
Proxy: ❌ DNS Only (TXT records cannot be proxied)
```

**Explanation**:
- `v=spf1` - SPF version 1
- `include:_spf.google.com` - Authorize Google's mail servers
- `~all` - Soft fail for unauthorized servers (recommended during setup)
- Alternative: `-all` for hard fail (strictest, use after validation)

### DMARC (Domain-based Message Authentication)

Provides reporting and policy for email authentication failures.

```
Type: TXT
Name: _dmarc
Content: v=DMARC1; p=none; rua=mailto:dmarc@designfitout.com; ruf=mailto:dmarc@designfitout.com; fo=1
TTL: 3600 (1 hour)
Proxy: ❌ DNS Only
```

**Explanation**:
- `v=DMARC1` - DMARC version 1
- `p=none` - Policy: monitor only (no action taken on failures)
- `rua=mailto:...` - Aggregate reports destination
- `ruf=mailto:...` - Forensic (failure) reports destination
- `fo=1` - Generate forensic reports for all failures

**Policy Progression** (recommended):
1. **Start**: `p=none` (monitor for 2-4 weeks)
2. **Intermediate**: `p=quarantine` (move suspicious emails to spam)
3. **Strict**: `p=reject` (reject unauthenticated emails)

### MTA-STS (Mail Transfer Agent Strict Transport Security)

Signals that an MTA-STS policy is available.

```
Type: TXT
Name: _mta-sts
Content: v=STSv1; id=2025-11-09
TTL: 3600 (1 hour)
Proxy: ❌ DNS Only
```

**Note**: Update the `id` value whenever you modify the MTA-STS policy file. Use a timestamp or incrementing version number.

## DKIM Records

DKIM (DomainKeys Identified Mail) cryptographically signs outgoing emails. These records are **generated by Google Workspace** and must be added manually.

### How to Generate DKIM Keys

1. Go to **Google Admin Console**: https://admin.google.com
2. Navigate to: **Apps → Google Workspace → Gmail → Authenticate email**
3. Click **Generate new record**
4. Select **2048-bit key** (recommended)
5. Copy the provided TXT record details

### Example DKIM Record

```
Type: TXT
Name: google._domainkey
Content: v=DKIM1; k=rsa; p=MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEA... (long base64 string)
TTL: 3600 (1 hour)
Proxy: ❌ DNS Only
```

**Important**:
- The selector name (e.g., `google`) may vary based on your Google Workspace setup
- The content will be a long string starting with `v=DKIM1; k=rsa; p=...`
- Some DNS providers require splitting long TXT records into multiple strings
- In Cloudflare, you can paste the entire record as-is

### Verification

After adding the DKIM record:
1. Wait 5-10 minutes for DNS propagation
2. Return to Google Admin Console
3. Click **Start authentication** to verify the DKIM setup

## Cloudflare Proxy Settings

### ✅ Proxy Enabled (Orange Cloud)

Use proxying for web content to benefit from Cloudflare's CDN, DDoS protection, and caching:
- Root domain (`@`) - **Recommended**
- `www` subdomain - **Recommended**
- `mta-sts` subdomain - **Recommended** (if serving policy through Cloudflare Pages)

**Requirements**:
- Valid SSL/TLS certificate (automatic with Cloudflare)
- Configure SSL/TLS mode: Full (Strict) or Full

### ❌ DNS Only (Gray Cloud)

Use DNS-only mode for records that must resolve directly to origin servers:
- **All MX records** - **REQUIRED** (email delivery won't work if proxied)
- **All TXT records** - **AUTOMATIC** (TXT records cannot be proxied)
- DKIM records - **AUTOMATIC** (TXT type)
- SPF records - **AUTOMATIC** (TXT type)
- DMARC records - **AUTOMATIC** (TXT type)

## TTL Recommendations

| Record Type | Recommended TTL | Reason |
|-------------|-----------------|--------|
| A (root) | 3600 (1 hour) | Balance between propagation speed and cache efficiency |
| CNAME | 3600 (1 hour) | Standard for subdomains |
| MX | 3600 (1 hour) | Email delivery reliability |
| TXT (SPF/DMARC) | 3600 (1 hour) | Standard for email security records |
| TXT (DKIM) | 3600 (1 hour) | Allow for key rotation |
| TXT (MTA-STS) | 3600 (1 hour) | Matches policy max_age |

**Notes**:
- Lower TTL (300-600s) during initial setup or when making changes
- Higher TTL (86400s / 24h) for stable, rarely-changed records
- Cloudflare's proxied records use automatic TTL optimization
